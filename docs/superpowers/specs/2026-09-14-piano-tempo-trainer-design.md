# 피아노 템포 트레이너 — 설계 문서

- 날짜: 2026-09-14
- 작성자: Seolhee Sun (Claude Code와 협업)
- 상태: 설계 승인됨, 구현 계획 작성 대기

## 1. 배경 / 목적

클래식 피아노(3/4박자에 셋잇단음표가 섞인 곡 등)를 느린 템포로 연습할 때, 기존 오디오 배속 조절(0.5배속 등)은 두 가지 문제가 있었다:

1. 피치가 같이 낮아지고 음질이 "테이프 늘어지는 소리"처럼 뭉개짐
2. 원곡 자체가 루바토(템포 변화)가 있어서 정박이 어디인지 파악하기 어려움

이를 해결하기 위해, 오디오를 늘리는 대신 **악보 데이터(MusicXML)를 원하는 BPM으로 처음부터 다시 연주**하고, 그 위에 정확한 메트로놈 클릭을 얹는 개인용 연습 도구를 만든다. 이번 대화에서 모슈코프스키 왈츠 Op.34 No.1으로 파이프라인(악보 파싱 → 템포 적용 → 페달 복원 → 신디사이저 렌더링 → 메트로놈 합성 → 믹스)을 프로토타입으로 검증했다. 이 문서는 그 검증된 로직을 재사용해서 실제 쓸 수 있는 도구로 만드는 설계다.

## 2. 목표 / 비목표

**목표 (v1)**
- 사용자가 자신이 가진 MusicXML(.musicxml/.mxl) 파일을 업로드
- 원하는 BPM으로, 피치 왜곡 없이, 실제 피아노 음색으로 재생
- 재생 중 슬라이더로 BPM을 즉시(끊김 없이) 조절
- 3/4(또는 악보의 박자표에 맞는) 메트로놈 클릭을 켜고 끌 수 있음 — **모든 박이 같은 음높이·세기** (강박 악센트 없음)
- 마디 단위로 구간을 지정해서 반복 재생 (어려운 구간 집중 연습)
- 집/연습실 등 같은 와이파이에서 휴대폰 브라우저로 접속해서 사용

**비목표 (v1에서 제외)**
- 곡 제목으로 검색해서 자동으로 악보를 찾아주는 기능 (IMSLP는 스캔 PDF만 제공하고 MuseScore 사용자 편곡본은 재배포 라이선스가 불분명해서, 별도의 저작권 검토 없이는 v1에 포함하지 않음)
- 로그인/계정/외부 인터넷 배포 (같은 와이파이 내에서만 동작)
- MIDI 입력 파일 지원은 나중에 고려 (v1은 MusicXML 우선, 이유는 다이내믹·페달 정보가 명시적으로 들어있기 때문. 테스트용 MIDI로 확인해본 결과, 벨로시티가 전부 동일하고 페달 정보가 아예 없는 경우가 있어 품질이 MIDI 출처에 따라 크게 달라짐)
- 악보 이미지 표시/따라가기 하이라이트
- "몇 초 전" 되감기 버튼 (마디 단위 구간 반복으로 대체하기로 사용자와 합의)

## 3. 전체 아키텍처

```
[PC]                                   [휴대폰/PC 브라우저]
 ┌─────────────────────┐   같은 와이파이   ┌──────────────────────┐
 │ 로컬 서버 (FastAPI)   │ ───────────────▶│ 웹페이지 (정적 HTML/JS) │
 │  POST /api/parse     │   JSON 응답      │  - Web Audio 재생 엔진 │
 │  (MusicXML 업로드)     │◀──────────────  │  - 피아노 샘플 신디사이저│
 │  music21 파싱 +       │                  │  - BPM 슬라이더/메트로놈│
 │  페달 이벤트 복원       │                  │  - 구간 반복 UI        │
 └─────────────────────┘                  └──────────────────────┘
```

- **서버는 오디오를 만들지 않는다.** 업로드된 악보를 분석해서 "음표/페달/박" 데이터를 JSON으로 한 번 만들어주는 역할만 한다. (이전 프로토타입에서 서버가 FluidSynth로 wav를 굽던 방식과 다름 — 실시간 BPM 슬라이더 요구사항 때문에 렌더링을 브라우저로 옮김)
- **실제 재생/템포 적용/메트로놈은 브라우저에서** Web Audio API로 실시간 스케줄링한다.
- 서버는 파이썬(FastAPI)으로 로컬에서 실행하며, 같은 와이파이의 휴대폰이 PC의 로컬 IP:포트로 접속한다. 외부 인터넷 노출 없음.

## 4. 서버: 악보 분석 API

`POST /api/parse` — multipart로 MusicXML(.musicxml/.mxl) 파일 업로드

처리 과정 (이번 대화에서 검증한 로직 재사용):
1. `music21`로 파싱
2. 시간표(time signature), 총 길이(quarterLength) 추출
3. 모든 음표를 순회하며 `{pitch(MIDI 번호), startQL, durationQL, velocity}` 목록 생성
4. `PedalMark` 스패너를 순회하며 시작/끝 절대 offset(quarterLength)을 계산 — 이때 `getOffsetInHierarchy`가 실패하는 케이스(Voice 안에 있는 음표 등)를 대비해 **site 체인을 직접 걷는 방식**으로 처리 (프로토타입에서 이 방식으로 40/41개 페달을 정상 추출함, 1개는 activeSite가 None인 orphan이라 스킵 — 이런 경우는 로그만 남기고 무시)
5. 마디별 박 목록 생성: `{offsetQL, measureNumber}` (시간표의 분자만큼 마디마다 반복)

응답 JSON 스키마:
```json
{
  "title": "Valse, Op. 34 No. 1",
  "timeSignature": {"numerator": 3, "denominator": 4},
  "totalQuarterLength": 1291.03,
  "notes": [
    {"pitch": 61, "startQL": 0.0, "durationQL": 1.0, "velocity": 80}
  ],
  "pedalEvents": [
    {"onQL": 134.0, "offQL": 138.0}
  ],
  "beats": [
    {"offsetQL": 0.0, "measure": 1},
    {"offsetQL": 1.0, "measure": 1},
    {"offsetQL": 2.0, "measure": 1}
  ],
  "warnings": ["페달 지시 1개를 위치 정보 부족으로 건너뜀"]
}
```

이 JSON은 **BPM에 독립적**이다 (모든 시간은 quarterLength 단위). 브라우저가 현재 BPM으로 실시간 환산한다.

## 5. 브라우저: 재생 엔진

**신디사이저**: 실제 피아노 녹음 샘플 기반의 경량 JS 신디사이저(WebAudioFont 방식)를 사용한다. 이전 프로토타입에서 쓴 FluidSynth+21MB 사운드폰트 대신, 웹/모바일에 맞게 압축된 작은 피아노 샘플 세트를 브라우저에서 직접 로드해서 쓴다. (음질은 실제 FluidSynth 렌더링보다 약간 단순화될 수 있음 — 실사용해보고 부족하면 WASM 기반 FluidSynth로 교체 검토)

**시간 환산 원리**: `실제 재생 시각(초) = 기준시각 + (offsetQL - 기준offsetQL) × 60 / 현재BPM`

- 재생 시작 시: 기준시각 = `audioContext.currentTime`, 기준offsetQL = 0 (또는 구간 반복 시작점)
- BPM 슬라이더를 움직이는 순간: 그 시점의 "현재 논리적 위치(offsetQL)"를 계산해서 기준offsetQL로 다시 설정하고, 기준시각도 그 순간의 `currentTime`으로 재설정 → 이후 스케줄링은 새 BPM으로 이어짐 (재생이 끊기지 않음)
- 메트로놈 클릭도 `beats` 목록에 같은 환산식을 적용해서 스케줄링 (음높이·세기 모두 동일하게 — 강박 악센트 없음)

**스케줄링 방식**: 약 25ms 주기로 폴링하면서, 앞으로 약 150ms 안에 재생될 음표/클릭을 Web Audio에 미리 예약(`source.start(when)`)하는 룩어헤드 방식 (표준적인 Web Audio 정밀 타이밍 패턴).

**모바일 자동재생 정책**: 사용자가 ▶ 버튼을 직접 눌러야 `AudioContext`가 시작됨 — 업로드 후 첫 화면에 재생 버튼이 반드시 노출되어야 함.

## 6. UI

**업로드 화면**: 파일 선택/드래그앤드롭 (.musicxml/.mxl만 허용, 그 외 확장자는 즉시 에러 메시지)

**연습 화면**:
```
제목: {title}
[▶/⏸]  [⏮ 처음부터]
BPM: [====●------] 55        (슬라이더 + 숫자 입력, 드래그 즉시 반영)
🔔 메트로놈  [ON/OFF]         (모든 박 동일 음높이·세기)
────●───────────  1:42 / 24:10   (진행바, 탭해서 이동)

[구간 시작 지정] [구간 끝 지정]  🔁 반복 [ON/OFF]
  → "구간 시작 지정": 현재 위치가 속한 마디의 시작(offsetQL)으로 스냅
  → "구간 끝 지정": 현재 위치가 속한 마디의 끝(다음 마디 시작 offsetQL)으로 스냅
     → 이렇게 해야 마디 전체가 항상 구간에 포함됨
  → 지정된 구간은 진행바 위에 하이라이트로 표시
  → 반복 ON 상태에서 구간 끝 도달 시 자동으로 구간 시작으로 복귀
```

## 7. 에러 처리

| 상황 | 처리 |
|---|---|
| 지원 안 되는 파일 형식 | "MusicXML(.musicxml/.mxl) 파일만 지원해요" 안내, 업로드 화면에서 즉시 차단 |
| music21 파싱 실패 (손상된 파일 등) | 에러 메시지와 함께 업로드 화면으로 복귀 |
| 페달 매핑 일부 실패 | 무시하고 진행, `warnings`에 남겨 콘솔/화면 하단에 작게 표시 |
| 박자표를 찾을 수 없음 | 4/4로 가정, 경고 표시 |
| 오디오 컨텍스트 시작 실패 (자동재생 차단 등) | "재생 버튼을 눌러주세요" 안내 |

## 8. 테스트 전략

- **서버**: 모슈코프스키 왈츠 샘플 파일로 회귀 테스트 1개 — 음표 개수, 페달 구간 개수(40개), 박 개수, 시간표(3/4)가 예상값과 일치하는지 확인. 이번에 겪었던 "페달 정보 누락" 버그의 재발을 막는 게 목적.
- **브라우저**: 자동화 테스트보다는 실제 휴대폰에서 재생하며 슬라이더 반응성·메트로놈 정확도를 직접 확인 (수동 QA). 필요하면 스케줄링 함수(offsetQL→실제시각 환산)에 대한 단위 테스트만 추가.

## 9. 향후 고려사항 (v1 이후)

- 여러 파일 보관/불러오기 (지금은 매번 업로드)
